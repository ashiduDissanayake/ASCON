# Vector formats

All files under `vectors/` are generated by `model/gen_vectors.py` from
`model/refmodel.py` -- regenerate with `python3 model/gen_vectors.py`,
don't hand-edit them.

## AEAD KAT text format (`pyascon/`, `NIST-KAT/`)

Line-oriented key/value pairs, one blank line between records:

```text
Key = 000102030405060708090A0B0C0D0E0F
Nonce = 000102030405060708090A0B0C0D0E0F
PT =
AD = 00010203
CT = 6F0A0F8A7F3D...
```

`Key`/`Nonce`/`PT`/`AD`/`CT` are hex, empty values are blank, and an
optional `Count` field is ignored by the parser. `CT` is ciphertext +
tag together. This is the canonical byte-oriented reference (it covers
Ascon's full byte-length range); the ACVP JSON vectors are kept
alongside it for the official NIST samples.

## Permutation submodule vectors (`vectors/*.vec`, for `tb/`)

Whitespace-separated, one vector per line. Each 320-bit state is five
concatenated 64-bit hex words, most-significant word first (`x0 x1 x2 x3
x4`), matching `ascon_permutation`'s `state_in`/`state_out` layout.

| File | Fields | Consumed by |
|---|---|---|
| `submodule_cases.vec` | `state_in state_out` (full 12-round permutation) | `tb/ascon_permutation_tb.v` |
| `pS_cases.vec` | `state_after_pC state_after_pS`, one line/round | `tb/ascon_pS_tb.v` |
| `pL_cases.vec` | `state_after_pS state_after_pL`, one line/round | `tb/ascon_pL_tb.v` |
| `round_cases.vec` | `state_before const_idx state_after`, one line/round | `tb/ascon_round_tb.v` |

All four come from `refmodel.py::permutation_stages`, which records the
pC/pS/pL intermediate state at every round (cross-checked against
`pyascon.ascon_permutation`).

## Controller (full AEAD) vectors (`vectors/controller_cases.vec`)

Whitespace-separated, positional (no field labels), one record per line:

```text
dir key nonce
ad_len ad_beat[0] ad_beat[1] ...
pc_len pc_beat[0] pc_beat[1] ...
tag_in
exp_beat[0] exp_beat[1] ...
exp_tag exp_auth_ok
```

- `dir`: `0` = encrypt, `1` = decrypt+verify.
- `key`/`nonce`/`tag_in`/`exp_tag`: 128-bit hex, same convention as
  `ascon_controller`'s ports of the same name.
- `ad_len`/`pc_len`: decimal byte counts (`pc_len` excludes the 16-byte
  tag). `pc_in` is plaintext for `dir=0`, ciphertext for `dir=1`.
- `*_beat[i]`: `ceil(len/16)` beats, 128-bit hex, packed stream-order
  (byte `i` in bits `[8*i +: 8]`) so a beat loads straight into a reg
  with `%h`. A length of 0 contributes zero beats. `exp_beat[i]` is the
  expected output stream (ciphertext for `dir=0`, plaintext for `dir=1`).
- `exp_auth_ok`: `0`/`1`, meaningful only when `dir=1`.

Negative-security cases (tampered ciphertext/tag, wrong key/nonce,
modified AD) still carry the RTL's real byte-exact output and tag --
computed via `refmodel.decrypt_raw`, not assumed equal to the original
plaintext -- because `ascon_controller` streams output and computes the
tag unconditionally, independent of the later `auth_ok` check. See
`model/gen_vectors.py::controller_cases` for how each case is built.
